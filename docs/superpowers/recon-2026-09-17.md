### 3.5 已知缺口与副作用（必须知道，不要当成 bug）

1. **`"8.1"` 这种合并维护条目会被多条正则同时命中**
   （`Maintenance on AI/ML for NR Air interface, NR MIMO Phase 5,  NES and NTN for NR and IoT`
   同时命中 ai_ml 和 mimo）。这是真实的多议题合并标题，不是误判，但下游要允许一条标题挂到多个 feature。
2. **`UE features for ...` 会被命中**（ai_ml / mimo / ntn / nes / lp_wus 都有这类子项）。
   如果血统只关心技术议题、不关心能力上报，需要再加一条排除式 `(?i)^UE features for`。本报告不替这个决定拍板。
3. **`network_energy_saving` 不收缩写 `NES`**。语料里 `NES` 单独出现过两次
   （`#119(H3) NES`、`#121(H2) MIMO, NES`），两次都是会场分组标题而非议题标题；
   `agenda.csv` 的 `"8.1"` 里也是缩写。收了 `\bNES\b` 会把分组标题一起收进来，所以本版不收。
4. **`isac` 只命中 H2 的完整议题名，不命中 `ISAC deployment scenarios` / `ISAC channel modelling` 这两条 H3 子项。**
   这是故意的：一旦放宽到 `\bISAC\b`，就会命中 6GR 的 `"10.8","ISAC"`。
   如果下游需要子项粒度，应该靠"父 heading 已命中"的层级关系下推，而不是放宽正则。
5. **ISAC 的血统起点是 #116，不是 #112。** #112–#115 的 1148 条 heading 里**一条 ISAC 都没有**
   （实测，见附录 A）。如果给 ISAC 配 `meetings: 112-`，前 4 次会议会是空结果。
6. **LP-WUS 在 #115 有一次断档**：#112–#114 有 SI（`Study on low-power wake-up signal and receiver for NR`），
   #115 一条都没有，#116 起变成 WI（`Low-power wake-up signal and receiver for NR (LP-WUS/WUR)`）。
   这是 SI 结项到 WI 立项之间的空窗，不是抓取失败。

### 4.2 重要修正：**这台服务器对"不存在的目录"返回的是 403，不是 404**

`sources.yaml` 里 RAN2/RAN3/RAN4/RANP 四处注释都写着"403，无法判定是限流还是该会议尚未开幕/目录未建立"。
这个歧义**现在可以消掉一半**。实测三条：

```
GET .../WG1_RL1/TSGR1_121/            -> 200，目录列表里只有 Docs / Inbox / Invitation / LS / Report，没有 Agenda
GET .../WG1_RL1/TSGR1_999/Agenda/     -> 403   （#999 这次会议根本不存在）
GET .../WG1_RL1/TSGR1_121/NoSuchDir_zzz/ -> 403（随手编的子目录名）
```

同一次会话、同一 UA、同样 5–10 秒间隔下，#123/#124/#125 的 Agenda/ 全部 200，#121/#122 连续三次 403。
二轮又对 #118/#119 做了同样的核实（见 §4.1 表格），结论一致：`Agenda/` 403，而根目录 200 且不含 `Agenda` 条目。
即 §4.1 表格里那四次 403（#118/#119/#121/#122）是**同一种情况**，四份根目录列表都已落盘、可原字节复核。
**结论：403 是"路径不存在"的表现，不是限流。** 正确的探测方法因此应改为：

> 先 GET 会议根目录（`TSGR1_<n>/`），从目录列表里判断有没有 `Agenda` 这个子目录条目；
> 有再去取 `Agenda/`。直接打 `Agenda/` 吃到 403 时，应判定为"该会议没有 Agenda 目录"，
> 而不是退避重试。

**但请注意本条的边界**：这只证明"403 覆盖了不存在的路径"，
**不能**证明"403 一定不是限流" —— 高频请求下是否另有一类 403，本次没有制造过载去验证，所以没有数据。
RAN2/RAN3/RAN4/RANP 的 `agenda_csv_since` 仍然是**未实测**，`verified: false` 应当保持，
但它们的 403 注释应该按上面这条改写，并且后续核实时改用"先看会议根目录"的方法。

我已经据此**只改了 `sources.yaml` 的注释文字，没有动任何一个取值**。

### 4.3 `artifacts: [minutes_docx, ...]` 的命名有误导性

实测 #112–#122 的纪要**全部**是 `.zip` 包裹的 docx，只有 #126 是裸 `.docx`（见 1.2 发现 A）。
字段名叫 `minutes_docx` 没问题，但 fetch 层必须实现"先找 .docx，找不到退到含 minutes 的 .zip 并解包"。
建议在该字段旁加一行注释说明，避免后续任务按字面实现成只认 `.docx`。
（`scripts/recon.py` 的 `unwrap_docx()` 已经是这个逻辑。）

但也**没有证据支持它就是最优下限** —— 我没有往 #111 及更早探测过。维持原值。
